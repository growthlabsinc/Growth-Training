# Story 3.5: Create Knowledge Deployment Scripts

## Status
Draft

## Story
**As a** developer,
**I want to** build automated deployment scripts for knowledge updates,
**So that** knowledge base updates can be efficiently deployed and maintained

## Acceptance Criteria
1. Scripts for batch upload of knowledge documents are functional
2. Version control system is implemented for knowledge tracking
3. Validation checks ensure document quality before deployment
4. Error handling prevents partial deployments
5. Progress tracking provides clear deployment status
6. Rollback capability allows reverting problematic deployments

#### File Locations (based on existing patterns)

- Knowledge data files can be stored in: `/scripts/knowledge-data/` for organization
[Source: Observed from deploy-angion-methods-admin.js structure]

#### Firebase Configuration
```javascript
const PROJECT_ID = 'growth-training-app';
const COLLECTION_NAME = 'ai_coach_knowledge';
```

[Source: Current Firebase project configuration]

#### Knowledge Document Schema
```javascript
{
  id: string,           // Unique identifier
  category: string,     // 'safety' | 'length' | 'girth' | 'eq' | 'equipment' | 'recovery'
  title: string,        // Display title
  content: string,      // Main content (can be lengthy)
  keywords: string[],   // Search keywords
  priority: number,     // 1-10 scale (10 = highest, used for safety)
  version: number,      // Version tracking (new field to add)
  updatedAt: timestamp, // Last update timestamp
  deployedBy: string    // Deployment script identifier
}
```
[Source: Story 3.2 implementation, enhanced with versioning]

#### Batch Operations Pattern
```javascript
const batch = db.batch();
documents.forEach((doc) => {
  const docRef = db.collection(COLLECTION_NAME).doc(doc.id);
  batch.set(docRef, doc);
});
await batch.commit();
```
Maximum batch size: 500 operations (Firestore limit)
[Source: Firebase documentation standards]

#### Required NPM Dependencies
- firebase-admin: Already installed, used for Firestore operations
- commander or yargs: For command-line argument parsing
- cli-progress: For progress bar display
- chalk: For colored console output (optional but helpful)
[Source: Standard Node.js deployment script patterns]

### Testing Standards
- Test scripts should be created in `/scripts/test/` directory
- Use Jest or Mocha for unit testing deployment functions
- Create mock Firestore for testing without affecting production
- Test validation functions with invalid document samples
- Verify rollback functionality with test deployments

### Deployment Safety Notes
- Always run dry-run mode first before production deployment
- Backup existing knowledge before major updates
- Validate all documents before batch commit
- Use transaction batching to prevent partial deployments
- Log all deployment activities for audit trail
