# Story 11.1: Anonymous Statistical ID Generation & Management

## Status
**Done**

## Story
**As a** Growth Training user who wants to contribute data to PE research,
**I want** an anonymous statistical ID generated for my data exports,
**so that** I can share my progress data with GrowthTrack without exposing my identity.

## Acceptance Criteria
1. Anonymous statistical ID is generated on first access (UUID-based, format: GT-XXXXXXXX)
2. ID is persisted in UserDefaults for consistency across exports
3. User can regenerate ID via Settings to break longitudinal linkage
4. Service provides `regenerateAnonymousId()` method that Settings UI will call after user confirmation (confirmation dialog implemented in Story 11.4)
5. No real userId or Firebase Auth UID is ever included in exports
6. Service provides clear help text explaining what statistical ID is and why it's used
7. Anonymous ID generation is logged for audit purposes
8. Service follows existing Swift service patterns (singleton, class-based)

## Dev Notes

### Service Architecture Pattern
[Source: Growth/Core/Services/KeychainService.swift, BiometricAuthService.swift, UserService.swift]

All services in Growth Training follow a consistent pattern:
- **Singleton pattern**: `static let shared = ServiceName()`
- **Private initializer**: `private init() {}`
- **Service identifier**: Use Bundle ID for namespacing
- **Class-based**: Prefer `class` over `struct` for services
- **Async methods**: Use `async throws` for Firestore operations

Example from KeychainService.swift:
```swift
class KeychainService {
    static let shared = KeychainService()
    private let service = Bundle.main.bundleIdentifier ?? "com.growthtraining.Growth"
    private init() {}

    // Public methods...
}
```

### UserDefaults Key Naming Convention
[Source: Growth/Core/Services/BiometricAuthService.swift, RemoteConfigManager.swift]

UserDefaults keys follow reverse-DNS pattern:
- Format: `com.growthlabs.{feature}.{setting}`
- Examples: `com.growthlabs.biometric.enabled`, `com.growthlabs.onboarding.completed`
- For this story: `com.growthlabs.anonymousStatisticalId`

### UUID Generation in Swift
[Source: Swift Foundation framework]

UUID generation is straightforward:
```swift
let uuid = UUID().uuidString // Returns full UUID like "E621E1F8-C36C-495A-93FC-0C247A3E6E5F"
let prefix = uuid.prefix(8)   // Take first 8 chars: "E621E1F8"
let uppercased = prefix.uppercased() // Ensure uppercase
let anonymousId = "GT-\(uppercased)" // Result: "GT-E621E1F8"
```

### Firestore Audit Logging Pattern
[Source: Growth/Core/Services/UserService.swift, SessionService.swift]

Firestore writes use async/await with error handling:
```swift
func logEvent() {
    Task {
        do {
            try await Firestore.firestore()
                .collection("audit_logs")
                .addDocument(data: [
                    "userId": Auth.auth().currentUser?.uid ?? "unknown",
                    "timestamp": FieldValue.serverTimestamp(),
                    "action": "action_name"
                ])
        } catch {
            print("Audit log failed: \(error.localizedDescription)")
            // Don't throw - audit logging should never block main functionality
        }
    }
}
```

### Rate Limiting Implementation
[Source: Epic 11 PRD - Privacy Best Practices]

Rate limiting prevents abuse of ID regeneration:
- Store last regeneration timestamp in UserDefaults
- Check time diff before allowing new regeneration
- 24-hour minimum interval recommended
- Return existing ID if within rate limit window

```swift
private let lastRegenerationKey = "com.growthlabs.lastAnonymousIdRegeneration"

func canRegenerateId() -> Bool {
    guard let lastDate = UserDefaults.standard.object(forKey: lastRegenerationKey) as? Date else {
        return true // First time, allow
    }
    let hoursSince = Date().timeIntervalSince(lastDate) / 3600
    return hoursSince >= 24
}
```

### Privacy Guarantees
[Source: Epic 11 PRD - Privacy & Ethics section]

Critical privacy requirements:
1. **No PII**: Never expose userId, email, Firebase Auth UID
2. **Anonymous ID format**: GT-XXXXXXXX (8 random chars)
3. **Opt-in only**: Export features require explicit consent
4. **User control**: Can regenerate ID to break longitudinal linkage
5. **Audit trail**: Track ID generation for compliance (but hash the ID in audit)

### Error Handling Strategy
[Source: Existing services pattern]

Service methods should:
1. **Never throw for ID generation**: Return String, not String?
2. **Fail gracefully for logging**: Don't block if Firestore write fails
3. **Return existing ID if rate limited**: Don't error, just return current ID
4. **Log errors to console**: Use `print()` for debugging
