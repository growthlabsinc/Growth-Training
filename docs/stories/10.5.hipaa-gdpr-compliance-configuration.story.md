### Firebase Security Rules Context
[Source: firestore.rules]

**Current PHI Protection:**
- All user data requires `request.auth != null`
- Users can only read/write their own documents (`userId == request.auth.uid`)
- Admin-only write access to public collections (growth_exercises, routines)
- Subcollections (stats, customRoutines, routineProgress, deviceTokens) protected by user ID

**Key Security Patterns:**
```javascript
function isSignedIn() { return request.auth != null; }
function isOwner(userId) { return isSignedIn() && request.auth.uid == userId; }
```

### Compliance Requirements

**HIPAA Requirements:**
- Business Associate Agreement (BAA) with Google Cloud
- PHI protection via authentication and access controls
- Audit logging for all PHI access
- Encryption at rest and in transit
- Minimum necessary access principle (IAM roles)

**GDPR Requirements:**
- Data Processing Agreement (DPA) with Google Cloud
- Data residency configuration (EU region for EU users)
- User consent management (opt-in for data collection)
- Data subject rights implementation (access, rectification, erasure, portability, restriction)
- Data breach notification procedures (72-hour window)
- Privacy by design and default

**Firebase-Specific Considerations:**
- Firebase Analytics: Not used for PHI (de-identified event parameters)
- Firebase Crashlytics: Covered by BAA but no PHI in crash traces
- Firebase Authentication: HIPAA-eligible, covered by BAA
- Cloud Firestore: HIPAA-eligible, covered by BAA
- Cloud Functions: HIPAA-eligible, covered by BAA
- Cloud Storage: HIPAA-eligible, covered by BAA
